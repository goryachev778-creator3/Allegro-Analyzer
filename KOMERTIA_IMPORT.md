# Автоматический импорт Komertia (Issue #1)

Изменение добавляет вкладку **Импорт Komertia** в существующее Streamlit-приложение. Пользователь загружает исходный файл, проверяет позиции и итоговые суммы, отмечает подтверждение и нажимает **Подтвердить импорт**. Ручной SQL и перенос файлов в Neon не нужны.

## Поддержанный реальный формат

- Safari `.webarchive` страницы `/client/orders/<UUID>`: HTML таблицы и исходные изображения (сохранить страницу в Safari через ⌘S → «Веб-архив»).
- `.html` той же страницы с явным указанием исходной ссылки. В этом случае фото могут остаться внешними URL; интерфейс предупреждает об этом.
- Существующий CSV/XLSX-импорт остаётся в настройках. Новый импорт не обещает автоматически распознавать произвольный XLSX/PDF поставщика.

Парсер читает локальный файл, не выполняет JavaScript и не обращается к сайтам с аккаунтом пользователя. Обрабатывает rowspan и общие расходы один раз, читает итоговые платежи/количество и **окончательную Cena szt.**; доставка, пошлина и оформление повторно равны нулю. Нулевое количество исключается. Фото из веб-архива сохраняются в существующих JSON-записях в исходном разрешении, не вырезаются из скриншота и не загружаются в Git. Есть лимиты файла, изображений и разрешения.

Если сумма Cena szt. × количество отличается от общего итога в пределах возможного округления до грошей, разница показывается отдельно. Исходные цены не подгоняются. Большие расхождения, некорректные платежи/количество, отсутствующие фото или конфликтующие ID блокируют импорт. Сокращённые самим источником варианты сохраняются как есть и требуют явного принятия в предпросмотре. Новые цены Allegro и ставки комиссии пустые; рыночная цена и реальная ставка по категории импортом не выдумываются.

## База, транзакции и совместимость SQL

Используется только текущий `ALLEGRO_DATABASE_URL` из Streamlit Secrets либо переменной окружения, TLS обязателен. Пароли/DSN не добавляются в исходники, вывод или журнал. Импорт требует `current_database() = 'neondb'`, существующую `public.allegro_state` и ключи `analysis` (массив) / `prices` (объект). Новая таблица или отдельное приложение не создаются. Локальная SQLite для подтверждённого импорта запрещена.

Как и в `neon-import-2026-10-19/01-check-ROLLBACK.sql`, используется блокировка строк, добавление в конец существующего массива, сохранение старых цен, проверки количества/стоимости и чтение после записи. Тип `value` может быть text/json/jsonb. UUID формируется из UUID заказа, product ID и варианта; совместим с ранее подготовленным SQL, а не основан на отображаемом LP.

Существующие записи, фото, цены, результаты и архивные флаги не перезаписываются. Повторный импорт пропускает существующие позиции; несовпадение количества или себестоимости существующей позиции отменяет транзакцию. Совпадающие архивные позиции не восстанавливаются автоматически. При подтверждении данные перечитываются под advisory lock и row lock, поэтому предпросмотр не считается актуальным снимком БД. Analysis, prices и журнал успешной операции пишутся в одной транзакции; при ошибке откатываются. Попытка записать обезличенную запись о неудаче выполняется отдельной транзакцией после отката; при недоступной БД журнал тоже может быть недоступен.

Журнал хранится под новым ключом `komertia_import_log` той же таблицы: ID операции, время UTC, выцена, дата партии, контрольные суммы, результат, добавлено/пропущено/архив. Секретов и содержимого фотографий в журнале нет.

Обычное автосохранение Streamlit получает контрольный хеш загруженного analysis. Если другой сеанс или импорт изменил БД, устаревшая таблица не перезаписывается: пользователю предлагается резервная копия и обновление страницы. Для импортов и основного автосохранения применяется общий advisory lock.

## Проверка и запуск после review PR

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m streamlit run app.py
```

Нужны существующее подключение Neon в Secrets и право читать/изменять записи `public.allegro_state`. Схема/таблица не создаются импортом; сеть развёрнутого приложения должна разрешать Neon. Оригинальные файлы выцены и реквизиты в PR не включены.

Проверено локально на реальном предоставленном веб-архиве 19.10.2026: 47 исходных строк, 41 активная позиция, 71 штука; платежи 1980.56 + 2502.63 = 4483.19; сумма округлённых Cena szt. × количество = 4483.17, расхождение 0.02. Все активные фото встроены из исходных файлов (600–1500 px); ID совпадают с подготовленными SQL. Интеграционная проверка SQL сервиса проводилась в изолированном PostgreSQL-движке PGlite с типами text/jsonb, включая повторный импорт; это НЕ тест на рабочей Neon.

Рабочая Neon из среды Codex недоступна: интеграции/секрета нет. Никакой производственный импорт, merge в main или деплой автоматически не выполняется. После review и развёртывания ветки проверить загрузку/предпросмотр, подтверждение на тестовой ветке Neon, повторный импорт и сохранность старых данных, затем использовать рабочую базу с актуальной резервной копией.
