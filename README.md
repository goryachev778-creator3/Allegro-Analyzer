# Allegro Analyzer

Веб-приложение на русском языке для сравнения прибыльности товаров Allegro по выгрузке Komertia. Поддерживает CSV и Excel `.xlsx`, выбор листа, сопоставление колонок, курс закупочной валюты, редактирование расходов, цен и комиссий, сортировку прибыли, поиск и цветовые статусы. Экспорт Excel включает все товары, расходы, результаты, цвета и методику; его можно загрузить повторно.

## Запуск

Требуется Python 3.12.

```bash
cd /workspace/Allegro-Analyzer
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

Локально откройте `http://localhost:8501`. Для облачного доступа используйте доступный механизм портов вашей платформы.

```bash
.venv/bin/python -m pytest -q
```

## Как работать

1. Загрузите CSV (UTF-8 или Windows-1250) либо Excel `.xlsx`. Старый `.xls` предварительно сохраните как `.xlsx`.
2. Выберите колонки выгрузки. Обязательна колонка названия товара. Для остальных полей можно задать общее значение по умолчанию; пустые ячейки выбранной числовой колонки считаются нулём. SKU сохраняются как текст.
3. Укажите курс PLN за единицу валюты закупки. Только закупочная цена пересчитывается по курсу; все остальные суммы вводятся в PLN.
4. Нажмите «Загрузить в таблицу», заполните расходы, цену продажи и комиссию Allegro. Расходы на партию сначала разделите на число единиц. Можно добавлять и удалять товары.
5. Изучите таблицу по убыванию прибыли и скачайте полный анализ в Excel. Каждое изменение таблицы автоматически сохраняется на сервере в SQLite; последний анализ восстанавливается после обновления страницы и перезапуска Streamlit. Экспорт служит отдельной резервной копией.

Встроены демонстрационный пример и скачиваемый CSV-шаблон. Конкретная схема Komertia не предполагается: пользователь сопоставляет поля своей выгрузки.

## Формулы и допущения

Все показатели — на одну единицу товара, в PLN. Пошлина = (закупка + доставка) × ставка пошлины / 100. Себестоимость включает закупку, доставку, пошлину, таможенное оформление, дополнительные расходы и невозмещаемый НДС. Ставка пошлины вводится пользователем по коду товара; автоматического определения ставки нет.

Прибыль = цена продажи − себестоимость − цена продажи × комиссия % / 100 − фиксированная комиссия. Маржа = прибыль / цена × 100%; ROI = прибыль / себестоимость × 100%. Нулевой знаменатель даёт неопределённый показатель, показанный прочерком. Расчёты выполняются без промежуточного округления; отображение — два знака.

Зелёный статус — положительная прибыль и маржа не ниже порога (по умолчанию 15%); жёлтый — неотрицательная прибыль с низкой маржой либо нулевая прибыль; красный — убыток. Нулевая цена трактуется как ещё не заданная и показывается серым.

Возмещаемый НДС не включайте в расходы. Закупка и продажа должны быть на сопоставимой базе НДС. Возвраты, упаковку, рекламу и логистику по Польше можно добавить в дополнительные расходы. Это управленческая модель, а не расчёт налоговой декларации. Импортированные текстовые поля в Excel сохраняются как текст, без выполнения формул.


## Автосохранение и повторный импорт

Рабочий анализ хранится в `data/analysis.sqlite3` (папка исключена из Git). Для другого постоянного пути задайте `ALLEGRO_DB_PATH`. Хранилище переживает перезапуск Streamlit, пока сохраняется диск; при размещении в контейнере подключите постоянный том. Это один общий анализ установки, без раздельных пользовательских аккаунтов. Не используйте его одновременно для независимых анализов разных пользователей.

После каждого изменения таблицы сохраняются все редактируемые поля, добавления и удаления строк. Индикатор «Сохранено» подтверждает запись; при ошибке диска показывается «Есть несохранённые изменения». Некорректное значение тоже сохраняется, чтобы не потерять ввод, но расчёт требует его исправления.

При повторном импорте товары сопоставляются по SKU (как текст, с сохранением ведущих нулей), а при пустом SKU — по названию без учёта регистра и пробелов по краям. Все поля найденных товаров берутся из сохранённого анализа, включая цены, комиссии и расходы. Новые товары берутся из выгрузки. Товары, отсутствующие в новой выгрузке, удаляются из рабочего набора. Дубликаты SKU и названий допустимы: каждый вариант сохраняется отдельной строкой. Для Komertia идентификатор строится по Produkt + Wariant и исходному ID строки (если выбран); иначе используются описательные поля исходной строки и номер повторения. Идентификаторы назначаются до исключения нулевых остатков. Для полностью одинаковых строк без исходного ID номер повторения зависит от их порядка: для гарантированного сопоставления таких строк выберите стабильный ID из выгрузки. В Excel идентификатор сохраняется в колонке `_position_id`, поэтому экспорт можно повторно импортировать без потери связи с вариантами. Старые анализы без идентификаторов переходят на новый формат; перенос старых цен по SKU/названию выполняется только при однозначном совпадении. Для обновления расходов существующего товара отредактируйте его строку вручную.

Сопоставление колонок, значения по умолчанию, курс и колонка остатка запоминаются при нажатии «Загрузить в таблицу». Профиль привязан к имени файла, листу и названиям колонок, поэтому действует и для обновлённой выгрузки с той же структурой. Колонка `Ilość` распознаётся автоматически; можно выбрать другую колонку остатков. Строки с нулевым остатком (включая пустые остатки, трактуемые как ноль) исключаются до объединения.

Демонстрационный пример заменяет непустой рабочий анализ только после подтверждения. «Сбросить текущий анализ» также требует подтверждения и очищает сохранённые товары, но сохраняет профили импорта. Эти действия необратимы: при необходимости заранее экспортируйте Excel.


Для данных Komertia колонка «Закупка PLN» содержит окончательную стоимость одной штуки: `Cena szt.` имеет приоритет; при её отсутствии используется `Razem / Ilość`. Доставка, пошлина и оформление, уже включённые в эту сумму, записываются нулём в отдельных полях. Дополнительные новые расходы можно вводить отдельно вручную. Сохранённые позиции из скриншотов автоматически переводятся из прежней разбивки в единую стоимость без изменения прибыли и введённых цен Allegro.


## Сохранение после нового деплоя Streamlit Cloud

Локальная SQLite НЕ гарантирует сохранность после пересборки, смены Python или удаления контейнера. В интерфейсе локальное сохранение помечено предупреждением. Для надёжного хранения нужна внешняя PostgreSQL-база (например, Neon или Supabase), находящаяся вне контейнера приложения.

1. До пересборки нажмите «Скачать резервную копию Excel». Она содержит рабочие поля и постоянные идентификаторы.
2. Создайте PostgreSQL-базу и получите строку подключения с TLS. Используйте отдельную базу/схему для этого приложения и пользователя с правами создания таблицы, чтения и записи.
3. В Streamlit Cloud: Manage app → ⋮ → Settings → Secrets добавьте `ALLEGRO_DATABASE_URL` со строкой подключения PostgreSQL. Значение вводите только в Secrets, никогда не в чат или GitHub. Для локального запуска можно задать одноимённую переменную окружения. Пример формы записи с заменяемыми реквизитами: `ALLEGRO_DATABASE_URL = "postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require"`.
4. Приложение создаёт таблицу `allegro_state` автоматически. Если внешняя база пустая и локальная SQLite ещё существует, текущий анализ переносится в неё; старый файл остаётся. Если контейнер уже потерян, используйте «Восстановить данные из резервной копии Excel», выберите копию, отметьте подтверждение и нажмите «Восстановить резервную копию».
5. Убедитесь, что статус — «Сохранено во внешней базе». Затем проверьте свой деплой: измените цену, обновите страницу и перезапустите приложение. Не считайте подключение готовым, пока такая проверка не выполнена.

Сохранение анализа и реестра цен/комиссий выполняется одной транзакцией. Реестр связан с постоянным ID позиции, а не отображаемым номером строки; цены удалённых из текущего набора позиций сохраняются для будущего импорта. При недоступной внешней базе приложение НЕ переключается незаметно на SQLite и показывает «Есть несохранённые изменения». Резервную копию текущей таблицы можно скачать даже при ошибке сохранения.

Данные из скриншотов получают постоянные UUID, записанные в каталоге. Старые идентификаторы автоматически переводятся в UUID с сохранением цен. Неоднозначные полностью одинаковые строки внешней выгрузки без собственного ID всё ещё требуют стабильного исходного ID для гарантированного соответствия вариантов.


## Фото и полные названия Komertia

В каждой позиции есть отдельные поля «Фото Komertia» и «Полное название Komertia». При импорте сопоставьте их с оригинальными колонками выгрузки. Сокращённые названия с многоточием не выдаются за полные; отсутствующие поля остаются пустыми. В разделе ручного заполнения выберите товар и вариант, вставьте оригинальное название или загрузите PNG/JPEG/WebP до 5 МБ. Фото хранится как data URI в существующей записи анализа PostgreSQL, поэтому отдельное файловое хранилище не требуется. При повторном импорте сохранённые фото и названия сохраняются по ID позиции.

Таблицы полных данных и результатов переносят длинные названия и варианты без обрезания. В редакторе расходов используется стандартная прокручиваемая сетка; полный текст всегда доступен ниже. Резервная копия Excel сохраняет крупные фотографии частями на отдельном листе и восстанавливает их без потерь.

Открытие анализа больше не удаляет дубликаты или позиции с нулевым остатком и не переводит автоматически старую разбивку расходов. Существующие товары, цены и расходы сохраняются; формулы расчётов не менялись.

## Польские названия и вставка фото

Основные таблицы показывают фото и одно поле `Nazwa produktu`: короткое польское название с подтверждёнными характеристиками. Поля `Товар`, `Produkt`, `Wariant` и полное название Komertia сохраняются для идентификации и резервного копирования, но скрыты из основных таблиц. В разделе исходных данных можно проверить оригинальную запись. Польское название хранится отдельно и сохраняется при повторном импорте. Сокращённые источники не позволяют установить все характеристики; неизвестные параметры не дополняются.

В таблице «Фото и названия товаров» щёлкните ячейку фото нужного товара и нажмите Cmd + V на Mac (Ctrl + V на других системах). На сайте Komertia предварительно выберите «Копировать изображение». Копирование ссылки не равнозначно копированию изображения. В той же ячейке доступна загрузка PNG/JPEG/WebP до 5 МБ. Нажатие на миниатюру открывает увеличенное фото. Вставка адресуется по постоянному ID товара, поэтому порядок строк не влияет на связь фотографии с товаром. Байты изображений сохраняются через существующее хранилище Neon, без изменения строки подключения, цен или формул.

## ZIP фотографий по исходным LP Komertia

В разделе «Импорт фотографий Komertia по исходным LP из ZIP» загрузите архив с именами `Komertia_LP_01.png`–`Komertia_LP_38.png` и нажмите «Сохранить фотографии ZIP в Neon». При наличии `mapowanie_LP.csv` его соответствия проверяются. Сопоставление использует `source_row`, исходный LP или постоянный ID каталога; отображаемый номер строки не используется. Импорт обновляет «Фото Komertia» и сохраняет восстановленный исходный LP в текущих записях, одной транзакцией, сохраняя порядок, названия, цены, формулы и реестр цен. Отсутствующий или противоречивый LP отменяет весь импорт. После сохранения уже существующие таблицы отображают миниатюры; увеличенный просмотр доступен в таблице фотографий. Архивы и сами фотографии не включаются в исходный код проекта.

При утрате `source_row` или замене ID импорт восстанавливает LP по первоначальным `Produkt`, `Wariant` и количеству из исторического каталога. Поля текущей нумерации `№` и `LP` не считаются доказательством исходного LP. Сопоставление не использует изменяемые цены и не выбирает вариант по порядку строк. Неоднозначные записи не изменяются автоматически. Однозначно восстановленные LP сохраняются при чтении анализа и повторно используются после перезапуска.

### Ручное сопоставление без исходных LP

После загрузки ZIP доступны все его миниатюры с обозначениями LP и все текущие товары в сохранённом порядке с польскими названиями. Для каждого товара выберите LP фотографии; рядом сразу появится предпросмотр. «Без изменения» оставляет существующее фото. Кнопка «Сохранить выбранные фотографии в Neon» записывает только выбранные изображения. Привязка выполняется по постоянному ID товара, без восстановления или угадывания его исходного LP. Названия, цены, формулы, порядок строк, исходные данные и реестр цен сохраняются. Если состав товаров в базе изменился во время выбора, запись отменяется и предлагается обновить страницу.

### Автоматическое сопоставление с предварительным просмотром

После загрузки ZIP нажмите «Автоматически сопоставить все фото». Приложение использует первоначальные LP/ID, Produkt, Wariant и количество из заказа; текущие номера строк не используются. Позиции с известным количеством 0 исключаются из операции, но сохраняются в анализе. Если исходные сведения утрачены, можно повторно использовать ранее вручную подтверждённое фото, только когда оно точно совпадает с единственным изображением ZIP.

Предварительный результат показывает польское название без изменений, исходный LP и миниатюру. Неоднозначные или отсутствующие совпадения перечисляются отдельно; найденные подтверждённые совпадения можно сохранить отдельно, не дожидаясь ручного выбора для остальных товаров. Только кнопка «Подтвердить и сохранить автоматически сопоставленные фото в Neon» записывает изображения. Перед записью повторно проверяется соответствие актуальным данным базы; цены, названия, формулы и порядок строк сохраняются.

## Главная страница и настройки

Главная страница содержит параметры анализа, индикатор сохранения, фильтры и показатели прибыльности, одну редактируемую таблицу товаров с фото, польским названием, закупкой, ценой Allegro, комиссиями, прибылью и маржой, а также экспорт полного анализа в Excel. Прибыль и маржа вычисляются автоматически и недоступны для ручного изменения. Порядок строк рабочего набора сохраняется; фильтры скрывают строки, не удаляя их из базы или экспорта.

Во вкладке «Настройки и импорт» находятся CSV/XLSX, ZIP фотографий, ручное и автоматическое сопоставление, вставка фото из буфера, исходные данные Komertia, резервная копия и её восстановление, демонстрационный пример, CSV-шаблон и методика. Опция показа всех расходов добавляет дополнительные редактируемые расходы в ту же основную таблицу. Добавление и удаление товаров доступны при снятых фильтрах. Подключение и сохранение Neon используются без изменений.

## Оригинальные названия Komertia

Основная таблица показывает отдельные `Produkt` и `Wariant` из исходных данных, без перевода, сокращения или придуманного продолжения. Исходные колонки `PRODUKT`/`WARIANT` распознаются независимо от регистра. При отсутствии отдельных полей оригинальный текст восстанавливается по сохранённому LP или постоянному ID каталога; неоднозначные записи не дополняются. Сокращённый текст скриншота сохраняется дословно. Прежнее `Nazwa produktu` остаётся архивным полем и не используется как оригинальное название.

При открытии восстановленные оригинальные поля сохраняются через существующее подключение PostgreSQL. Фотографии, закупка, продажи, количество, постоянные ID и ранее подтверждённые сопоставления сохраняются. При новом импорте можно выбрать исходный LP Komertia; он сохраняется отдельно от отображаемого номера строки. Идентификация использует исходные Produkt/Wariant и стабильный исходный идентификатор, а не текущий порядок.


### Частичное сохранение и итоговая строка

Кнопка подтверждения доступна, если найдено хотя бы одно автоматическое совпадение. Сохраняются только совпавшие фотографии; несопоставленные товары и их существующие фото остаются без изменений, а ручной выбор по LP доступен в том же разделе. Автоматическое назначение не заменяет уже сохранённое отличающееся фото. После записи показывается количество сохранённых изображений.

«ИТОГО A1632» исключается из таблицы товаров, показателей, экспорта анализа и списков сопоставления. Исходная итоговая запись остаётся в базе и резервной копии, без удаления её данных. Produkt, Wariant, закупка и количество товаров не изменяются.

## Компактная основная таблица

Ширина основной таблицы подстраивается под доступное место при изменении окна и боковой панели. Узкие колонки «№», «Фото», «Закупка», «Allegro», «Ком. %», «Ком. zł», «Прибыль» и «Маржа %» оставляют остальное пространство оригинальным Produkt и Wariant. Внутренняя вертикальная прокрутка и закреплённая шапка поддерживаются стандартным редактором Streamlit; редактирование закупки, цены и комиссий сохраняется. Проверено отсутствие горизонтального переполнения на настольных размерах 1280, 1440 и 1920 пикселей. Дополнительные расходы редактируются для выбранного товара в «Настройки и импорт», не расширяя основную таблицу. Заголовки сокращены только в интерфейсе; поля базы, экспорт и формулы не переименованы.


## Улучшение фотографий для Allegro

В «Настройки и импорт» откройте «Улучшить фото для Allegro». Выберите фотографию товара, сохранённую в базе, либо загрузите исходный PNG/JPEG/WebP до 5 МБ. Доступны увеличение 1×/2×/4×, мягкое снижение шума с защитой краёв и мягкая резкость. Пропорции и кадр сохраняются; генерации деталей, изменения насыщенности, перерисовки надписей или добавления комплектации нет. Увеличение разрешения не восстанавливает отсутствующие детали источника. Результат ограничен 16 мегапикселями.

Белый фон применяется только к существующей прозрачности; непрозрачный фон не вырезается, чтобы не повреждать товар. После обработки доступны сравнение с оригиналом, скачивание улучшенной PNG-копии и скачивание неизменённого исходного файла. Перед размещением проверьте мелкие надписи и детали. Обработка не записывает изменения в Neon и не заменяет исходные фотографии; улучшенная копия хранится только в текущей сессии до скачивания.

### Массовое улучшение фотографий

В «Настройки и импорт» → «Улучшить фото для Allegro» нажмите «Улучшить все фотографии». Для всех фотографий, загруженных в товары, применяются 2×, мягкое уменьшение шума и резкость. Прогресс показывает «Обработано X из Y»; товары без фото пропускаются и учитываются отдельным счётчиком. Итоговая строка заказа не считается товаром.

После обработки доступен один ZIP с улучшенными PNG-копиями и `photos-report.json`, связывающим файлы с ID, Produkt и Wariant. Ошибка отдельного изображения не прерывает остальные; причины показаны в интерфейсе и отчёте. Внешние ссылки, не содержащие загруженных байтов изображения, отображаются как ошибки и требуют загрузки исходного файла. Общий размер копий ограничен 128 МБ. Оригиналы, данные товаров и Neon не изменяются. Обработка одного фото и скачивание его оригинала остаются доступными. ZIP хранится только в текущей сессии до скачивания.

## Качество фото непосредственно в таблице

Колонка «Фото» показывает исходные изображения. Если в той же записи сохранён более крупный оригинал (`Фото Komertia (оригинал)`, `Фото оригинал` или `Original photo`), выбирается доступный исходник с наибольшим разрешением. Интерполяция 2×/4× и скачиваемые улучшенные копии не подменяют оригиналы в таблице.

При наведении появляется предпросмотр исходной фотографии с её фактическим размером в пикселях. Он не растягивает маленький файл, в том числе на Retina. Для файлов с длинной стороной меньше 800 пикселей выводится уведомление о низком разрешении; реальная чёткость зависит от исходника. Ширина таблицы и колонок сохранена. Предпросмотр получает фото из текущей отображаемой ячейки, включая прокрутку, без изменения связей товаров.

Цена и другие данные сохраняются с исходным полем фотографии: отображение более крупного оригинала не записывает его вместо сохранённого фото в Neon. Функции улучшения и ZIP-скачивания остаются отдельными инструментами в настройках.

## Проверка дубликатов

В «Настройки и импорт» → «Проверка дубликатов товаров» показаны повторные записи, исходные LP, цены, комиссии, фото и результат объединения. До установки флажка подтверждения и нажатия кнопки ничего не удаляется. Первая строка остаётся на прежнем месте, пустые поля дополняются из повторов. Разные характеристики, конфликтующие заполненные поля и сокращённые названия разных LP не объединяются. Изменение данных после просмотра требует нового подтверждения; сохранение выполняется в транзакции существующего хранилища Neon.

CSV/XLSX и повторная загрузка исходного каталога добавляют только новые позиции: существующие записи и введённые данные не заменяются. Интерфейс показывает число обнаруженных и пропущенных повторов. Изображения и формулы расчётов не меняются. Совпадение текущего номера строки не используется как идентификатор товара.

## Архив четырёх товаров без цены и закупка с доставкой

При первом открытии сохранённого анализа из 25 товаров приложение проверяет исходные строки №12, 13, 15 и 17. Если их цены Allegro равны нулю, записи помечаются архивными, без удаления или изменения остальных полей. Дальше архив определяется сохранёнными признаками записей, а не пересчитывается по текущему номеру строки. Несовпадение количества исходных товаров или ненулевая цена в указанной строке блокирует перенос и отображается в настройках.

В этом анализе главная таблица и Excel содержат активные товары с положительной ценой Allegro. Архив доступен в «Настройки и импорт → Архив товаров», полная резервная копия по-прежнему включает все записи. Если фактически заполненных цен меньше 21, приложение сообщает реальное количество, не назначая цены самостоятельно.

Для этого рабочего анализа закупка считается уже включающей транспорт и таможню. Комиссия = Allegro × комиссия % / 100; прибыль = Allegro − закупка − комиссия − доп. расходы; маржа = прибыль / Allegro × 100. Сохранённые поля доставки, пошлины, оформления, НДС и фиксированной комиссии не перезаписываются, но не начисляются повторно. Под таблицей показана итоговая строка: прибыль при продаже по одной штуке каждого активного товара и арифметическая средняя маржа. В Excel есть отдельный лист «Итоги». Старые примеры и другие наборы сохраняют прежнюю методику.


## Импорт следующих заказов из файла

Исходные данные новых заказов загружаются через CSV/XLSX в «Настройки и импорт». Они не встраиваются в исходный код. Импорт сохраняет source_order, исходный source_row, Ilość, Produkt, Wariant и постоянный _position_id. Для каждого заказа используйте отдельные постоянные ID. Нулевые количества исключаются; существующие записи и правки сохраняются при повторном импорте.

В главной таблице есть фильтр заказа. Позиции новых заказов доступны даже без цены Allegro; её и комиссию нужно заполнить самостоятельно. Итоги прибыли включают только товары с заданной ценой. При импорте фотографий ZIP обязательно выбирается заказ: одинаковые LP разных заказов не смешиваются. Прогнозная себестоимость из Razem / Ilość уже включает указанные поставщиком расходы и не начисляется повторно.
